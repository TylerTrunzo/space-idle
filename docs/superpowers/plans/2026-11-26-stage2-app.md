# Stage 2: Playable App (Map and Panels) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Flutter app (Android, web; iOS-ready) that plays the stage-1 economy: star map home screen, Mission Control planet panel, Production/Crew/Trade tabs, autosave, offline catch-up with a "while you were away" summary, and save export/import.

**Architecture:** `app/` is a Flutter package in the existing pub workspace that depends on `game_core`. A single `GameController` (a `ChangeNotifier`) owns the `GameEngine` and `GameState`, ticks once per second, applies commands, autosaves through a `SaveStore`, and exposes read-only view models built from `buildFlowReport`. Widgets never touch `GameState` directly except through view models and `controller.run(Command)`. Content JSON is embedded into a generated Dart file so the same bundle works on every platform.

**Tech Stack:** Flutter 3.50.1 / Dart 3.14 at `/opt/flutter/bin`, `shared_preferences` (save storage), `flutter_test`. Android APK builds run in GitHub Actions (the Android SDK can't be downloaded in the dev container). Web builds and tests run locally.

**Spec:** `docs/superpowers/specs/2026-11-26-space-idle-design.md` (sections 5.3, 6.7, 9, 11 stage 2).

## Global Constraints

- The UI renders state read-only and changes it only via `GameController.run(Command)` (spec 5.3). No game rule lives in the app. If a rule is missing from `game_core`, add it there with tests.
- **Home = star map. Tapping a planet opens the Mission Control panel** as a bottom sheet that drags to full screen on phones, and as a side panel at widths ≥ 840 px (spec 9).
- **Palette (Mission Control):** background `#0B1020`, panel `#111A30`, border `#1F2D4D`, interactive cyan `#5FE1FF`, warning amber `#FFB547`, deficit red `#FF6470`, surplus green `#63E6A4`, text `#CFE3FF`, muted `#8EA3C9`. Data and number text uses a monospace face (`fontFamily: 'monospace'` with `fontFamilyFallback: ['RobotoMono', 'Courier New']`). No network font fetching at runtime.
- **Accessibility:** state is conveyed by icon + text as well as color, tap targets ≥ 44 px, text scales with system settings (no clamping).
- **Offline catch-up** uses `GameEngine.catchUpOffline` with the wall-clock time since the last save. Base cap is 12 h (from content rules).
- **Autosave** every 30 s, on app pause/hide/detach, and after `importSave`/`newGame`.
- Number display always goes through `formatNumber` from `game_core`. Rates show as `+1.24K/s` / `-3/s`.
- Original names and art only. Planets and ships are drawn procedurally (CustomPainter), with no image assets needed.
- Android `applicationId` is the placeholder `com.spaceidle.game`. The final id is chosen before the first Play upload (spec 3).
- Run `flutter` via `/opt/flutter/bin/flutter`. Commit after each task with the session attribution trailer.
- Implementers may load the `flutter:widget-composition`, `flutter:adaptive-layout`, `flutter:accessibility-as-code`, `flutter:custom-canvas-and-gestures`, `flutter:ui-states-and-feedback` and `flutter:widget-golden-and-a11y-testing` skills for conventions. Where they conflict with this plan, this plan wins (e.g. state management is a plain `ChangeNotifier`, not Riverpod).

## Review Focus

1. **Corrupt or foreign save in storage at launch** (e.g. from an older build): the app must not crash. Show "Your save couldn't be loaded", offer to export the broken text and start a new game. (Task 2 test.)
2. **Clock going backwards** (device time changed): a negative time away simulates nothing and does not throw. (Task 2 test.)
3. **Rapid taps on +crew / upgrade** while a tick runs: commands apply in order, the UI never shows stale "affordable" state after a failure, and failures show a short message. (Task 6 test.)
4. **Narrow phones (360×640) and large text (2.0 scale):** the planet panel and top bar don't overflow. (Tasks 4 and 6 tests.)
5. **Very large numbers** (credits 1e40): the top bar and buttons stay readable (scientific format) and layout doesn't break. (Task 4 test.)

### Task 2: GameController, saves, clock, offline catch-up

**Files:** Create `app/lib/game/save_store.dart`, `clock.dart`, `game_controller.dart`. Test: `app/test/game/game_controller_test.dart`.

**Interfaces:**
- Consumes: `loadEmbeddedContent`, `GameEngine`, `SaveCodec`, `OfflineSummary`, `Command`, `CommandResult`.
- Produces:
  - `abstract interface class SaveStore { Future<String?> read(); Future<void> write(String text); }`, `PrefsSaveStore` (key `save_v1`), `MemorySaveStore`.
  - `abstract interface class Clock { DateTime now(); }`, `SystemClock`, `FakeClock(DateTime start)` with `advance(Duration)`.
  - Save envelope (stored text): `{"savedAt": <epoch ms>, "save": <SaveCodec.encode text>}`.
  - `class GameController extends ChangeNotifier { GameController({required Content content, required SaveStore store, required Clock clock, int newGameSeed}); Future<StartResult> start(); GameState get state; GameEngine get engine; FlowReport get flow /* recomputed after every tick/command, for the player faction */; String get playerId; CommandResult run(Command cmd); void tickSeconds(double seconds) /* used by the 1 s Timer and tests */; Future<void> save(); Future<OfflineSummary?> resume() /* app resumed: catch up from last save time */; String exportSave(); Future<ImportResult> importSave(String text); Future<void> newGame(); void startTimer(); void stopTimer(); String? lastError /* message of the last failed command, cleared on next success */; OfflineSummary? pendingAwaySummary /* set by start/resume when away ≥ 60 s; UI shows it then calls clearAwaySummary() */; void clearAwaySummary(); }`
  - `sealed class StartResult` → `StartedNew`, `Loaded`, `LoadFailed(String brokenText, String reason)`. On `LoadFailed`, the controller starts a new game in memory but does not overwrite storage until the player confirms via `newGame()` or `importSave`.
  - `sealed class ImportResult` → `Imported`, `ImportFailed(String reason)`.
  - Lifecycle: `app.dart` wires an `AppLifecycleListener`. `onPause`/`onHide`/`onDetach` → `save()` + `stopTimer()`; `onResume` → `resume()` + `startTimer()`.
- [ ] **Step 1: Failing tests** (all with `MemorySaveStore` + `FakeClock`, no timers):
  - Empty store → `StartedNew`, and the store is written.
  - Saved game + clock advanced 2 h → `Loaded`, `pendingAwaySummary.secondsSimulated == 7200`, and state time advanced 7200.
  - Clock advanced 30 h → simulated 43200 (cap).
  - Clock moved back 1 h → nothing simulated, no throw.
  - Garbage in store → `LoadFailed`; store still holds the garbage until `newGame()`.
  - `run(invalid)` sets `lastError` and leaves state JSON unchanged; then `run(valid)` clears `lastError` and notifies listeners.
  - Export/import round trip gives identical state; `importSave('nope')` → `ImportFailed`.
  - `tickSeconds(10)` advances `state.time` by 10 and notifies.
  - Autosave: `tickSeconds` accumulating ≥ 30 s of ticks triggers `store.write` once.
- [ ] **Step 2–4:** Run (fail), implement, run (pass). `flutter analyze` clean.
- [ ] **Step 5:** Commit `feat(app): game controller with autosave and offline catch-up`.

### Task 5: Star map

**Files:** Create `app/lib/ui/map/star_map.dart`, `app/lib/ui/map/star_map_painter.dart`. Test: `app/test/ui/star_map_test.dart`.

**Interfaces:**
- Produces: `StarMap({required GameController controller, required void Function(String bodyId) onSelect, String? selectedId})`. Layout: the system's star at the center; each body on a circle of radius `r = base + orbit × gap` at a stable angle (derived from a hash of the body id, so it doesn't move between launches; deterministic, no `Random()`). Body size and color come from body type (rocky `#B08968`, asteroid `#8A7A6A`, ice moon `#9FE8FF`, gas giant `#C56CFF`, volcanic `#FF8A5B`). Owned bodies get a cyan ring plus a label. Unowned bodies are dimmed with an "Unclaimed" label. Routes are drawn as curved lines between bodies. Each in-flight shipment is a dot interpolated along its route by `(time − departAt)/(arriveAt − departAt)`. If `Shipment` lacks `departAt`, derive it as `arriveAt − travelSeconds(from, to)`. A bottleneck on a body shows a small amber `!` badge. Wrap the map in `InteractiveViewer` (pinch/zoom, min 0.5, max 3). Use a `Ticker` for smooth shipment motion between 1 s ticks: interpolate with the wall-clock fraction since the last tick, clamped to 1. Respect `MediaQuery.disableAnimations`.
- Hit testing: tapping within `max(24 px, body radius + 8)` of a body calls `onSelect`. Each body also has a `Semantics(button: true, label: "<name>, <owned|unclaimed>")` overlay, so screen readers and tests can find it.
